Prompting best practices

Ten habits that make Claude faster, cheaper, and more predictable on helpdesk work. Every rule below reduces tokens without reducing quality.

Start every prompt here

Role, task, constraint. Memorize this shape — it covers 90% of helpdesk prompts.

You are [role]. [Task]. [Constraints / format].

You are an IT support specialist. Classify this ticket as Hardware, Software, Access, or Network. Reply with just the category name.

The ten habits

Each one with the version to avoid and the version to send.

01

Be specific upfront — no warmup text

Tokens spent on pleasantries are wasted. Open with the ask.

Avoid

Hey Claude, I hope you're doing well! I was wondering if maybe you could help me think about…

Send

Summarize the 3 main causes of this ticket delay in bullet points.

02

State the output format explicitly

If you need a table, say table. Three bullets, say three bullets. Ambiguity makes the model write more than you need.

Avoid

Write something about the server outage.

Send

Write a 2-sentence Slack update about the server outage. Tone: calm and professional.

03

Give context once

Every follow-up resends the whole conversation, so costs compound. One detailed message beats six short ones.

Avoid

Six short messages refining one answer.

Send

One message carrying role, task, format, and constraints.

04

Use role + task + constraint

The structure at the top of this page. For classification work it produces a one-word reply — the cheapest possible output.

You are an IT support specialist. Classify this ticket into Hardware, Software, Access, or Network. Reply with just the category name.

05

Cap the response length

The single biggest lever on output cost. The model respects explicit limits.

In 2 sentences… In under 100 words… Reply with only the action item.
06

Skip “think step by step” on simple tasks

Chain-of-thought earns its cost on genuinely complex problems — a multi-system outage, a conflicting policy call. On a ticket triage it just adds tokens. Use it only when answer quality depends on it.

07

Say what you want, not what you don't

Negatives are less reliable and pad the prompt.

Avoid

Don't write a long response. Don't use jargon. Don't include a disclaimer.

Send

Write one short paragraph in plain English, no disclaimer.

08

Reuse prompts for recurring work

Summarizing a ticket, writing a handoff note, classifying a request — save the prompt that worked. Consistent outputs, no bloat, no reinvention.

09

Paste the section, not the document

Summarizing one policy clause does not require the other nineteen pages. More input is more tokens processed on every turn that follows.

10

One task per prompt, usually

Five unrelated asks force one long multi-part answer — split them. Closely related asks (“summarize this ticket, then draft the reply”) are fine bundled.
